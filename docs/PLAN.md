# 实施计划与路线图 — 便捷翻译

> 版本: 0.1.0 | 最后更新: 2026-06-09

---

## 总览

采用**分阶段交付**策略，每阶段产出可用的版本。不追求一次性追平沉浸式翻译的全部功能，而是先做核心、快速可用、持续迭代。

```
MVP (v0.1)         v0.2            v0.3            v1.0
核心双语翻译    →   多引擎 + 缓存   →   交互增强   →   发布 Chrome Store
   2-3周             2-3周              2-3周            1周
```

### 超出原计划的附加功能

| 功能 | 说明 |
|------|------|
| 内存缓存 | 翻译→还原→再翻译秒出（1200x 加速），不会话丢失 |

### 验收标准

### 验收标准
- 在 Options 页面填入 DeepL/Claude API Key，选择引擎后翻译生效
- 翻译一段已缓存文本，第二次请求毫秒级返回
- Ollama 本地模型测试通过（需本地运行 Ollama）
- **API 代理**：无 Key 用户选择代理 → 翻译成功 → 余额正确扣减
- **API 代理**：余额不足时提示充值，不执行翻译
- **API 代理**：邮箱验证码登录成功 → Token 持久化 → 关闭扩展重开无需重新登录
- **支付**：充值回调幂等，同一订单号重复回调不重复加余额
- **尾量豁免**：余额不足以覆盖整次翻译但不足额 ≤ ¥0.3 → 免费完成 → 提示"余额已用完"

## 开发约定

### 分支策略

```
main          ← 稳定版本（每个阶段的完成状态）
  └─ dev      ← 开发主线
       └─ feat/xxx  ← 功能分支
```

### 提交规范

遵循 `.trae/rules/tdd.md` 的 TDD 格式：

```
[红] 添加 xxx 测试用例
[绿] 实现 xxx 功能
[重构] 优化 xxx 代码结构
```

### 文件大小限制

- 单文件 ≤ 300 行
- 单函数 ≤ 30 行
- 超过则拆分

### 测试要求

- 每个翻译适配器必须有单元测试（mock API 响应）
- DOM 文本提取/注入逻辑必须有单元测试（jsdom）
- 关键用户路径必须有 E2E 测试（Playwright）

## 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| Chrome Web Store 审核变严（MV3 限制） | 中 | 高 | 紧跟 WXT 社区动态，提前适配 |
| Google 翻译非官方 API 被限流 | 高 | 中 | 默认提示用户配置 DeepL/Claude API Key |
| Manifest V3 Service Worker 休眠导致长翻译中断 | 中 | 中 | 分片翻译 + 断点续传机制 |
| 大网页（5 万+ 文本节点）性能问题 | 中 | 中 | 虚拟滚动式分批翻译 + Worker 线程 |
| 与网站自身的翻译机制冲突 | 低 | 低 | 检测 `html[lang]` 变化，智能判断 |
