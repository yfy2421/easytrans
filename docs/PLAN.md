# 实施计划与路线图 — 便捷翻译

> 版本: 0.2.0 | 最后更新: 2026-06-12

---

## 总览

采用**分阶段交付**策略，每阶段产出可用的版本。不追求一次性追平沉浸式翻译的全部功能，而是先做核心、快速可用、持续迭代。

```
MVP (v0.1)         v0.2              v0.3            v1.0
核心双语翻译    →   多引擎 + 体验打磨   →   交互增强   →   发布 Chrome Store
   2-3周             4-6周               2-3周            1周
```

### 目标

**2A — 免费 NMT 引擎**：拓展免费神经网络翻译引擎（百度、Yandex、Bing、有道），用户无需 Key 即可翻译。
**2B — LLM 引擎**：DeepL/OpenAI/Claude/Ollama 等，自带 Key 可选，同时解锁真正的原生替换模式。
**2C — 体验打磨**：悬停原文、双语样式、缓存持久化。从沉浸式翻译借鉴的轻量改进。
**2D — API 代理（商业化）**：不想折腾 Key 的用户按量付费。标为可选路线，与其他子阶段解耦。

## 阶段 2A：免费 NMT 引擎（预计 2 周）

> Google 不是唯一免费的。搬运沉浸式翻译的 Yandex/Bing 逆向工程代码，再逆向百度（中国用户主力引擎）。

### 引擎对比

| 引擎 | 优势 | 端到端延迟 | 令牌机制 | 来源 |
|------|------|-----------|---------|------|
| Google | 质量最高、110+ 语言 | 海外 200-500ms | TK hash | ✅ 已搬 |
| 百度 | 国内直连、中英最佳 | 国内 50-150ms | sign 签名 | 待逆向 |
| Bing | 微软 NMT、质量稳定 | 中等 | IG + iid | 沉浸式翻译有 |
| Yandex | 免费、欧洲语言强 | 中等 | SID | 沉浸式翻译有 |
| 有道 | 国内备选、中英日韩 | 国内 80-200ms | sign | 待逆向 |
| LibreTranslate | 开源自建、完全免费 | 自建实例 | 无需 | 社区 |

## 开发约定

### 分支策略

```
main          ← 稳定版本（每个阶段的完成状态）
  └─ dev      ← 开发主线
       └─ feat/xxx  ← 功能分支
```

### 提交规范

遵循 `.trae/rules/tdd.md` 的 TDD 格式：

```
[红] 添加 xxx 测试用例
[绿] 实现 xxx 功能
[重构] 优化 xxx 代码结构
```

### 文件大小限制

- 单文件 ≤ 300 行
- 单函数 ≤ 30 行
- 超过则拆分

### 测试要求

- 每个翻译适配器必须有单元测试（mock API 响应）
- DOM 文本提取/注入逻辑必须有单元测试（jsdom）
- 关键用户路径必须有 E2E 测试（Playwright）

## 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| Chrome Web Store 审核变严（MV3 限制） | 中 | 高 | 紧跟 WXT 社区动态，提前适配 |
| Google 翻译非官方 API 被限流 | 高 | 中 | 默认提示用户配置 DeepL/Claude API Key |
| Manifest V3 Service Worker 休眠导致长翻译中断 | 中 | 中 | 分片翻译 + 断点续传机制 |
| 大网页（5 万+ 文本节点）性能问题 | 中 | 中 | 虚拟滚动式分批翻译 + Worker 线程 |
| 与网站自身的翻译机制冲突 | 低 | 低 | 检测 `html[lang]` 变化，智能判断 |
